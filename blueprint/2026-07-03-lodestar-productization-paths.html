0 판단의 전제 — 자산 vs 갭

보유 자산 (실측 검증)
  • RDB→온톨로지 파이프라인 (PostgreSQL·MySQL·DDL·샘플)
  • AI 관계 판정: 실 DB 97→9 정밀 필터 + 근거
  • 확정 루프: 제안→승인(세이브포인트)→그라운딩→재임포트 병합
  • 확률적 신뢰도(자기일관성) · 영향도 · 챗 · 휴지통 · 영속
  • 실 DB read-only 불가침 원칙 (신뢰 자산)
갭 (제품화 관점)
  • AI 의미추정이 샘플 전용 — 실 DB 미연결 (E12)
  • 관계 발굴 recall 미측정 — withvtm FK 72개가 정답셋 (E13)
  • 산출물(문서) 부재 — 도구 밖 소비물 없음 (E14)
  • 단일 사용자·인메모리 · 인증 없음 · claude -p 로컬 의존
  • Oracle/Tibero 미지원 (국내 엔터프라이즈 관문)
핵심 차별점 재정의 — 경쟁 도구의 산출물은 1회성이다. Lodestar의 정체성은 "복원한 지식이 죽지 않는 루프": 사람이 확정한 의미가 재스캔에도 살아남고 다음 추론의 앵커가 된다. 어떤 경로든 이 루프가 메시지의 중심이어야 한다.

1 네 가지 경로

A · 서비스 가속기 진입 1~2개월

제품을 팔지 않고, 레거시 분석 프로젝트를 이기고 빨리 끝내는 무기로 쓴다.
타깃
자사 컨설턴트 → 파트너 SI/SM 수행사
수익
프로젝트 원가 절감 · 엔게이지먼트당 사용료 · 파트너 건당 라이선스
기술 구현 방향
  • 포터블 패키징(Docker/단일 JAR) — 고객사 내부망 구동, claude -p 로컬이 오히려 장점(데이터 외부 유출 없음)
  • E12 실 DB 의미추정 + E14 보고서(테이블 사전·관계·영향도 PDF/HTML) = 딜리버러블
  • read-only 감사 로그 → 고객사 보안 승인 통과 장치
마케팅 / GTM
  • 사내 2개 프로젝트 실전 → "4주→3일" 전후 사례
  • 제안서 표준 슬라이드화 → 파트너 SI 2~3곳 무상 파일럿 → 유료 전환
리스크: "도구"로 고착 · 담당자 의존 · 서비스 매출 한계
KPI: 리드타임 단축률 · 산출물 재사용 수 · 파트너 유료 전환

B · 엔터프라이즈 온프렘 진입 9~15개월

국내 금융·공공·제조의 차세대/전환사업 앞단 자산실사 플랫폼.
타깃
차세대·클라우드 전환 앞둔 조직 · SM 수행사
수익
서버 연간 라이선스(DB 수 기준) + 유지보수 15~20% + 구축 용역
기술 구현 방향
  • 멀티유저(인증/RBAC/동시편집/이력) — 단일 인메모리 구조의 근본 개조
  • 영속 재설계 + 스케줄 자동 재스캔·병합(E9 확장)
  • Oracle·Tibero·MSSQL 커넥터 (SchemaSource 이음새로 국소 확장)
  • 망분리 대응 LLM: 사내 sLLM/프라이빗 API — AiAdvisor 교체점. 품질 재검증 필수
  • ISMS-P·감사로그·접근통제
마케팅 / GTM
  • ISP/PMO 컨설팅사 제휴(방법론 탑재) · PoC 1건 무상
  • 조달 등록·GS인증 · 백서("FK 없는 DB 관계를 AI로 복원한 실측")
  • 판매 수치: E13 recall 벤치 결과("관계 복원율 N%")
리스크: 영업 6~12개월 · 망분리 LLM 품질 · Oracle 방언 비용 · 소수 인원 지원 부담
KPI: PoC→계약 전환율 · 계약 단가 · 갱신율

C · 글로벌 개발자 SaaS 진입 6~9개월

"DDL 붙여넣으면 60초 안에 AI가 문서·관계·영향도" — 셀프서브 PLG.
타깃
글로벌 스타트업~미드마켓 백엔드 팀
수익
Freemium: 무료 1프로젝트 → 팀 $19~49/월
기술 구현 방향
  • 멀티테넌트 클라우드 · 빌링(Stripe) · SSO
  • AiAdvisor → Anthropic API 전환
  • DDL-only 모드 전면화: "DB에 접속하지 않는다" — SaaS 신뢰 장벽 해소, 이미 구현된 경로가 무기
  • GitHub 연동: 마이그레이션 스캔 → PR마다 문서 갱신 (E9 병합이 빛나는 지점)
  • 웹 UX 전면 개선 + 영어화
마케팅 / GTM
  • 가입 없는 데모 페이지(DDL→즉시 그래프+AI 라벨) = 퍼널 입구
  • SEO/콘텐츠("AI database documentation") · HN/dev 커뮤니티 런칭
  • 메시지: 단발 생성이 아닌 confirmed-knowledge loop
리스크: 인접 시장 밀집 · 소규모 팀의 글로벌 마케팅 체력 · 확정 루프 가치 전달 난이도 · 낮은 단가
KPI: 데모→가입 전환 · WAU · 무료→유료 전환 · MRR

D · AI-네이티브 (MCP) 진입 2~4주 · 레버리지 최고

확정된 DB 지식을 AI 에이전트가 소비하는 컨텍스트 서버(MCP)로. 원 비전 "Empower AI" 직행.
타깃
사내 코파일럿 만드는 플랫폼팀 · text-to-SQL 정확도가 아쉬운 팀
수익
단독보다 A/B/C의 프리미엄 모듈 · API 과금
기술 구현 방향
  • MCP 서버: 온톨로지·관계·확정 사실·영향도를 도구로 노출 — 백엔드가 이미 있어 소형 에픽
  • text-to-SQL 그라운딩 API: 질문 → 관련 테이블/관계/확정 라벨 컨텍스트 팩
  • 컨텍스트 랭킹에서 확정(세이브포인트) 지식 우선 — 루프가 AI 품질로 직결
마케팅 / GTM
  • 오픈소스 MCP 서버 공개 → 기술 블로그 → 인바운드
  • 데모 서사: "코파일럿에게 레거시 DB를 가르쳤다" — 확정 전/후 정확도 비교
  • Claude 생태계(MCP 디렉터리) 등재
리스크: 단독 수익화 불명확 · MCP 표준 진화 속도 · 캐리어(A/B/C) 필요
KPI: MCP 연동 수 · 확정 전/후 질의 정확도 개선폭 · 인바운드 리드

3 권고 — 단계적 하이브리드 (결정 게이트)

0~3개월

공통 선결(§4) + A 착수(사내 2개 프로젝트 실전) + D 얇게(오픈소스 MCP 공개)
근거: 둘 다 기존 자산 직결·저비용. A는 매출 접점, D는 기술 브랜드 선점.

3~6개월

A 사례 수치화("N주→N일") + E13 recall 벤치("관계 복원율 N%") — 판매 가능한 증거 확보

6개월 게이트

증거가 방향을 정한다:

→ B 투자
국내 엔터프라이즈 견인(PoC 문의·파트너 수요)이 강할 때. Oracle·멀티유저·망분리 LLM에 투자
→ C 투자
글로벌 인바운드(MCP·데모 트래픽)가 강할 때. 클라우드·PLG에 투자
한 줄 논리 — 팀이 작고, 자사가 보안 SI 맥락(온프렘 친화·한국 채널)이며, 고객 0호(자사 DB)가 이미 있다. A는 오늘 돈이 되고, D는 내일의 포지션을 선점하며, B/C는 증거가 정한다.

# Lodestar 진척도 로드맵 (비평 대응, 점진적 수치 상승)

> 작성일: 2026-07-02
> 상태: 승인됨 (진행 순서 확정)
> 목적: "잘 만든 ERD 뷰어"에 머물지 않고, 비평(토이 검증·AI 해자 미구현)을 정면으로 넘어 제품 완성도를 단계적으로 끌어올린다.

## 설계 3원칙 (사용자 지정)

1. **디자인보다 "표현"** — 초반 미관은 후순위. 각 에픽의 완료 정의 = *샘플 데이터로 동작을 눈으로 보여주는 데모*.
2. **단계마다 기능 테스트 가능** — 각 이슈는 샘플 주입 → 결과 확인이 되는 수직 슬라이스.
3. **AI 관점 난이도** — AI 개발 기준: 보일러플레이트·LOC는 싸다. 비싼 것은 **모호함·실데이터 지저분함·외부 호출·품질 검증**.

## 작업 방식

- 에픽 = GitHub 마일스톤, 실행 단위 = 이슈. (`CLAUDE.md` 규칙)
- 모든 구현은 이슈 브랜치 → PR로만 `main`에 반영.
- AI 기능은 **`claude -p`(headless CLI) subprocess 호출**로 구현 (API 키 미사용).

## 진행 순서 (확정): E1 → E3 → E2 → E4 → E5 → E6

E1으로 진짜 검증 기반을 깔고, 해자인 E3(AI 의미복원)를 **초반에** 검증한다 — 제품 전제가 틀렸다면 싸게 알아낸다.

| 에픽 | 목표 | 완료 데모 | AI 난이도 |
|---|---|---|---|
| **E1 Reality Harness** | 지저분한 대규모 레거시 샘플 주입 | 버튼 1번 → 100테이블 레거시가 그래프에 뜸 | 낮음 |
| **E3 AI Semantic Enrichment** ⭐ | 샘플행+이름 → AI가 의미 라벨/설명 후보 | 암호명 샘플 → `TB_CUST_MST="고객 마스터"` 제안 | 중(품질·외부호출) |
| **E2 Implicit Relationship Recovery** | FK 없는 관계를 휴리스틱(+AI)으로 발굴 | FK 0개 샘플 → 관계 후보 자동 표시 | 중(정밀도) |
| **E4 Impact Analysis** | 그래프 도달성으로 영향도 | 테이블 클릭 → 영향권 하이라이트 | 낮음 |
| **E5 Persistence** | 온톨로지 프로젝트 저장/로드 | 임포트→종료→재실행→그대로 | 낮~중 |
| **E6 AI Chat** | 온톨로지 자연어 Q&A | "customers-orders 관계 설명" → 답변 | 중 |

# Lodestar 제품화 청사진 — 4가지 경로 분석

> 작성일: 2026-07-03 · 상태: 전략 검토 문서
> 전제: E1~E11 완료, 자사 실 DB 2개(withvtm 102T/FK72, withcollector 118T/FK0) 검증 완료 시점의 분석.

---

## 0. 판단의 전제 — 지금 가진 자산과 갭

| 자산 (실측 검증됨) | 갭 (제품화 관점) |
|---|---|
| RDB→온톨로지 파이프라인 (JDBC PostgreSQL/MySQL + DDL + 샘플) | AI 의미추정이 **샘플 전용** (실 DB 미연결 — E12) |
| AI 관계 판정: 실 DB에서 97→9 정밀 필터 + 근거 | 관계 발굴 **recall 미측정** (E13: withvtm FK 72개를 정답셋으로 활용 가능) |
| 운영 모델 루프: 제안→승인(세이브포인트)→그라운딩→재임포트 병합 | **산출물(문서) 부재** — 도구를 안 여는 사람이 소비할 결과물 없음 (E14) |
| 확률적 신뢰도(자기일관성), 영향도, 챗, 휴지통, 프로젝트 영속 | 단일 사용자·인메모리, 인증 없음, `claude -p` 로컬 의존 (AiAdvisor 이음새로 교체 가능) |
| 실 DB **read-only 불가침** 원칙 (신뢰 자산) | Oracle/Tibero 미지원 (국내 엔터프라이즈 필수) |

**핵심 차별점 재정의:** 경쟁 도구(ERD 툴, "AI가 스키마 설명" 류)는 산출물이 1회성이다. Lodestar의 정체성은 **"복원한 지식이 죽지 않는 루프"** — 사람이 확정한 의미가 재스캔에도 살아남고 다음 추론의 앵커가 된다. 어느 경로를 택하든 이 루프가 마케팅 메시지의 중심이어야 한다.

## 경로 A — 서비스 가속기: 사내 도구 → SI/SM 엔게이지먼트 무기

**한 줄:** 제품을 팔지 않고, 레거시 분석 **프로젝트를 이기고 빨리 끝내는 무기**로 쓴다.

| 항목 | 내용 |
|---|---|
| 타깃 | 1차: 자사 컨설턴트/엔지니어. 2차: 파트너 SI/SM 수행사 |
| 가치 제안 | 고객사 레거시 DB 실사·문서화 리드타임 단축 (수작업 수 주 → 수 일), 제안서 차별화("AI 기반 자산 실사 방법론") |
| 수익 모델 | 내부: 프로젝트 원가 절감. 외부: 엔게이지먼트당 도구 사용료 or 산출물 프리미엄. 파트너 라이선스(건당) |
| 필요 투자 | **낮음 — 1~2개월.** 대부분 이미 구현됨 |

**기술 구현 방향**
- 포터블 패키징: Docker/단일 JAR — 컨설턴트 노트북·고객사 내부망에서 구동 (`claude -p` 로컬 의존이 오히려 장점: 고객 데이터가 외부로 안 나감)
- E12(실 DB 의미추정) + E14(보고서 생성: 테이블 사전·관계도·영향도 PDF/HTML) — 딜리버러블의 몸통
- read-only 감사 로그: "귀사 DB에 어떤 쿼리를 던졌는지" 증빙 → 고객사 보안 승인 통과 장치
- 보고서 템플릿 브랜딩 (제안서/완료보고서에 바로 삽입)

**마케팅/GTM 방향**
- 사내 프로젝트 2건에 실전 적용 → **전/후 시간 비교 사례** 확보 ("4주 → 3일")
- 제안서 표준 슬라이드화, 영업 조직 교육
- 파트너 SI 2~3곳 무상 파일럿 → 건당 과금 전환

**리스크:** 제품이 아닌 "도구"로 고착, 특정 담당자 의존, 서비스 매출 한계.
**KPI:** 프로젝트 리드타임 단축률, 프로젝트당 산출물 재사용 수, 파트너 유료 전환 수.

## 경로 B — 엔터프라이즈 온프레미스: Legacy Knowledge Platform

**한 줄:** 국내 금융·공공·제조의 **차세대/전환사업 앞단 필수 자산실사 플랫폼**으로 판다.

| 항목 | 내용 |
|---|---|
| 타깃 | 금융/공공/제조 정보시스템 부서, 차세대·클라우드 전환 앞둔 조직, SM 수행사 |
| 가치 제안 | "전환사업 전 시스템 자산 실사 + 살아있는 지식 베이스" — 인수인계·온보딩·영향도까지 상시 운영 |
| 수익 모델 | 서버 연간 라이선스(DB 수/코어 기준) + 유지보수 15~20% + 구축 용역 |
| 필요 투자 | **높음 — 9~15개월, 3~5인** |

**기술 구현 방향**
- 멀티유저: 인증/RBAC, 동시 편집, 변경 이력 — 현 단일 인메모리 구조의 근본 개조
- 영속 재설계: 온톨로지의 DB 저장(or 트리플스토어), 스케줄 기반 자동 재스캔+병합(E9 확장)
- **커넥터 확장: Oracle·Tibero·MSSQL** — 국내 엔터프라이즈 관문 (SchemaSource 이음새 덕에 국소 확장)
- **망분리 대응 LLM**: 고객사 내부 GPU 서버의 sLLM 또는 프라이빗 API — `AiAdvisor` 인터페이스가 이 교체를 위해 존재. 단 sLLM에서 판정 품질 재검증 필수
- ISMS-P/감사로그/접근통제 등 컴플라이언스 체크박스

**마케팅/GTM 방향**
- ISP/PMO 컨설팅사 제휴(그들의 방법론에 탑재), 차세대 발주 앞둔 조직에 **PoC 1건 무상**
- 공공: 조달 등록(디지털서비스몰), GS인증 취득
- 세미나/백서: "레거시 지식 자산화 — FK 없는 DB의 관계를 AI로 복원한 실측 사례" (withcollector 사례 익명화)
- 판매 수치 무기: E13 recall 벤치 결과 ("실 운영 DB 관계 복원율 N%")

**리스크:** 영업 사이클 6~12개월, 망분리 환경 LLM 품질, Oracle 방언 대응 비용, 소수 인원으로 엔터프라이즈 지원 부담.
**KPI:** PoC→계약 전환율, 평균 계약 단가, 갱신율, 커넥터별 스캔 성공률.

## 경로 C — 글로벌 개발자 SaaS: PLG (Product-Led Growth)

**한 줄:** "DDL 붙여넣으면 60초 안에 AI가 문서·관계·영향도를 준다" — 셀프서브 SaaS.

| 항목 | 내용 |
|---|---|
| 타깃 | 글로벌 스타트업~미드마켓 백엔드 팀, 문서화가 밀린 팀, 신규 합류 개발자 |
| 가치 제안 | 살아있는 스키마 문서 + AI 관계 복원. 온보딩 시간 단축 |
| 수익 모델 | Freemium: 무료 1프로젝트 → 팀 $19~49/월. 연간 선결제 할인 |
| 필요 투자 | **중~높음 — 6~9개월 + 지속적 마케팅 체력** |

**기술 구현 방향**
- 멀티테넌트 클라우드, 빌링(Stripe), 이메일/SSO 로그인
- `AiAdvisor` → Anthropic API 전환 (배포 필수)
- **DDL-only 모드를 전면에**: "당신 DB에 접속하지 않는다, 스키마 텍스트만" — SaaS 신뢰 장벽 해소. **이미 구현돼 있는 경로**가 핵심 무기
- GitHub 연동: 마이그레이션 파일에서 스키마 자동 추출·PR마다 문서 갱신 (E9 병합이 여기서 빛남)
- 웹 UX 전면 개선 + 영어화 (현재 "표현 우선" 수준에서 제품 수준으로)

**마케팅/GTM 방향**
- **가입 없는 데모 페이지**: DDL 붙여넣기 → 즉시 그래프+AI 라벨 (전환 퍼널의 입구)
- SEO/콘텐츠: "AI database documentation", "recover foreign keys" 등 — 검색 수요 존재 영역
- HN/Reddit/dev.to 런칭, 오픈소스 일부 공개로 인바운드
- 차별화 메시지: 단발 생성이 아닌 **confirmed-knowledge loop** ("문서가 스키마 변경에도 살아남는다")

**리스크:** 인접 시장 밀집(dbdocs/dbdiagram/DataHub + LLM 붐), 소규모 팀의 글로벌 마케팅 체력, 확정 루프의 가치를 셀프서브에서 전달하기 어려움, 낮은 단가.
**KPI:** 데모→가입 전환율, WAU, 무료→유료 전환율, MRR.

## 경로 D — AI-네이티브: 에이전트를 위한 시맨틱 레이어 (MCP)

**한 줄:** 복원·확정된 DB 지식을 **AI 에이전트가 소비하는 컨텍스트 서버(MCP)**로 노출한다. 원 비전 "Empower AI"의 직행 경로.

| 항목 | 내용 |
|---|---|
| 타깃 | 사내 AI 어시스턴트/코파일럿을 만드는 플랫폼팀, 에이전트 개발사, text-to-SQL 정확도에 목마른 팀 |
| 가치 제안 | 에이전트가 "어느 테이블을 조인해야 하나", "이 컬럼 바꾸면 뭐가 깨지나"를 **사람이 확정한 지식** 기반으로 답함 — 환각이 아닌 승인된 사실 |
| 수익 모델 | 단독보다 **A/B/C의 프리미엄 모듈**로. 또는 API 호출 과금 |
| 필요 투자 | **낮음 — 2~4주.** 백엔드가 이미 있어 MCP 래퍼는 소형 에픽. **레버리지 최고** |

**기술 구현 방향**
- MCP 서버: 온톨로지 조회·관계·확정 사실·영향도를 도구(tool)로 노출 → Claude 등 에이전트가 직접 활용
- text-to-SQL 그라운딩 엔드포인트: 질문 → 관련 테이블/관계/확정 라벨 컨텍스트 팩 반환
- 컨텍스트 랭킹에서 **확정(세이브포인트) 지식 우선** — 확정 루프가 AI 품질로 직결되는 지점

**마케팅/GTM 방향**
- 에이전트/MCP 생태계 물결 편승: **오픈소스 MCP 서버 공개** → 기술 블로그 → 인바운드
- 데모 서사: "코파일럿에게 우리 레거시 DB를 가르쳤다" — 확정 전/후 text-to-SQL 정확도 비교
- Claude 생태계(MCP 디렉터리) 등재

**리스크:** 단독 수익화 불명확, MCP 표준 진화 속도, "모듈"이라 캐리어(A/B/C)가 필요.
**KPI:** MCP 연동 수, 에이전트 질의 정확도 개선폭(확정 전/후), 인바운드 리드 수.

## 권고 — 단계적 하이브리드 (결정 게이트 방식)

한 경로에 올인하지 않고, **저비용 경로(A+D)로 증거를 모아 6개월 게이트에서 B/C를 결정**한다.

```
[0~3개월]  공통 선결(아래) + A 착수(사내 2개 프로젝트 실전) + D 얇게(오픈소스 MCP 공개)
              └─ 근거: 둘 다 기존 자산 직결·저비용, A는 매출 접점·D는 기술 브랜드
[3~6개월]  A 사례 수치화("N주→N일") + E13 recall 벤치 결과 확보("관계 복원율 N%")
[6개월 게이트]
   ├─ 국내 엔터프라이즈 견인(PoC 문의·파트너 수요)이 강하면 → B 투자 (Oracle·멀티유저·망분리 LLM)
   └─ 글로벌 인바운드(MCP·데모 트래픽)가 강하면      → C 투자 (클라우드·PLG)
```

근거: 팀 규모가 작고, 자사가 보안 SI 맥락(온프렘 친화·한국 채널)이며, 고객 0호(자사 DB)가 이미 확보돼 있다. A는 오늘 돈이 되고, D는 내일의 포지션을 선점하며, B/C는 증거가 정한다.
